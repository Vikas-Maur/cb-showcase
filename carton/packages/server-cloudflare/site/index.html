About

In this project, I ported Cardboard's Mac app to Windows, created a git for video system called Carton, and a live collaboration feature using Cloudflare.

  1. The Windows app was simply created by patching the extracted code, from Cardboard's ASAR package, for Windows. Using the patch system itself, the integration of the Carton and live collab features was done, along with improvements and bug fixes along the road.
  2. Carton, the git for video feature, works by storing each of the user's or the agent's changes in a SQLite/IndexedDB database (based on the platform), with merging done at leaf level and features like comparing diffs, resolving conflicts, creating various cuts etc.
  3. About the live collab feature, I didn't intend to create it at first, but as I was creating Carton, I just felt it to be a natural thing to go alongside the git system so that both of those could complement each other.

My approach

All the development was done via Opus 5.5 in this project, with GPT 6.1 Sol for reviews, in T3 Code on an EC2 instance and my Windows machine together.

I first started with laying out the requirements and asking Opus to come up with a plan to build that. I asked Opus to create a criticiser agent whose job must be to criticise whatever plan it comes up with, and both must prove each other's points correct/wrong through verifiable methods.

I ran that at night and didn't expect it, but that run took more than 6 hours. And that's what my recent tech learnings from watching videos on YouTube tell me, that having a limit is very important.

After the plan came, the Opus agent started to develop the plan. My main development process mainly revolves around the agent verifying, appropriately benching and improving the scores, and testing like a real user would.

Also, as I was editing videos myself using the built Cardboard versions, that also was a key factor in identifying a lot of places which needed improvements and bug fixes.

Previously, the agent just had that EC2 instance and hence wasn't able to test with a GPU or on a real Windows. Hence, I connected my Windows machine via T3 Code and provided it access to my machine. That helped it create benchmarks and perform verification on an actual machine, and helped improve the codebase more.

But that quickly became a blocker for me, as it was hijacking my machine while testing it out. Hence, eventually I got annoyed and asked it whether testing on another virtual desktop on my machine is possible, and it was, and that really made things easier for me.

Along with that, while testing the live collab feature, I provided Cloudflare access to the agent so that it can bench it properly and come up with a cost calculator for it, to determine how much live collaboration would actually cost.

What I learnt

I didn't really look at much code throughout the development, and most of the heavy lifting was done by Opus. And hence (again) my actual editing and testing was really important, and that made me find a lot of issues myself.

I got to know about Cardboard's current systems, where up to 20 latest revisions are being stored currently, about project.json and the timeline.tsx formation etc.

One of the key things I enjoyed learning while building this project was that on my 144 Hz display, for a 30 fps video, my GPU was redrawing the frames 144 times a second, even with nothing playing. I fixed that part (the editor now rests when idle), but during playback it still draws at the screen's rate. Learning about this was very fun.

Apart from that, I have a basic understanding of how Carton works, and of the Cloudflare live sync feature. I got to use Cloudflare for the first time and learn about Durable Objects, R2 etc.

What will I work on at Cardboard (if I get to)?

Firstly, I like working across the stack.

Currently, I built three things, and hence my focus was a little distributed. While building the Windows version, I really wanted to make it extremely great. But I wasn't sure whether I should just focus on that only or also on the mentioned hard problems, and hence I currently chose to build on the hard problems and make them my priority.

But yeah, I would really want to work on the video editor, be it the web version or the Electron app versions. I would really like to put my heart and soul and focus on building the core editor, improving performance, making it more reliable etc.

But yeah, I also do like all the backend stuff, the live sync feature for example. So, like I can work across the stack, I would love to work across the stack.
